## 自选走势对比

左侧“走势对比”可按名称或代码混选最多 8 项，支持沪深 A 股、东方财富行业板块和 6 个主要 A 股指数。选择和图表形式保存在当前浏览器；20／60／120／250 日控制图表、区间涨幅与相关性，支持缩放、图例隐藏和 JSON 数据导出。

- 默认“K 线对照”按对象上下排列红涨绿跌的 K 线与实际成交额，各图使用独立价格轴、相同日期，十字线和缩放联动。股票采用同一版本的前复权开高低收，指数采用实际点位。旧的仅收盘价缓存自动补齐；缺少完整 OHLC 或成交额时留空，不从收盘价伪造 K 线。刷新数据保留当前缩放，换对象或区间时重置。
- “叠加走势”按所有已加载对象的共同有效起点归零，比较前复权股票收盘价和公布指数点位的变化，使用加粗、高辨识度实线；不把不同单位的原始价格直接叠加。两种视图使用相同区间和统计。历史较短时明确缩短区间，无法加载的对象保留缺失状态。
- 仅在交易日北京时间 16:10 后纳入当天日线。页面每分钟检查，所选对象的日线异步更新；首次拉取每项最长 40 秒，失败保留旧数据、15 分钟后可自动重试，手动重试至少间隔 60 秒。此页不是盘中分时对比。
- Pearson 相关性使用相同交易日的每日收益，至少 20 个共同有效样本。缺失日不前向填充、不用跨多日收益替代单日收益。相关性描述历史关系，不证明因果；行业指数可能包含所选个股。
- 复权序列使用腾讯免费接口，失败尝试新浪；行业使用东方财富，指数优先复用本地采集。来源和截止日逐项展示。复权序列整批更换、独立缓存，不参与成交撮合，不改写模拟账户、训练特征或历史账本。缺乏可对齐的日线时显示原因。
- 接口：`/api/comparison/catalog`、`/api/comparison?ids=stock:600519,stock:000858,index:sh000300&window=60`。导出包含当前对象、日期、复权收盘价、区间变化、相关性样本数和来源；图表缩放不改变导出与统计区间。

## 原私有云端架构（未迁移）

本节描述原私有项目，所述采集与训练工作流不包含在本公开仓库中；不能按以下步骤直接得到已迁移的云端研究服务。

云端采用私有 GitHub 仓库，工作流为 `.github/workflows/cloud-research.yml`。`config.json` 中配置 `github_repo`，也可通过 `ASHARE_GITHUB_REPO` 覆盖。

1. 把代码推送到私有仓库的默认分支。
2. 核实账号剩余 Actions 免费额度、存储与超额费用阻断设置。额度与其他项目共享；本项目不会自行打开付费使用。
3. 在仓库变量中设置 `CLOUD_FREE_USAGE_VERIFIED=true`。未设置时所有云端任务跳过。
4. 手动运行 `probe`，验证 GitHub 网络环境可访问关键行情源。
5. 手动运行 `update` 或 `close`，验证报告发布、检查点上传和本地下载。

工作流北京时间：07:35 初版、08:35 更新、09:05 补跑、16:10 收盘更新。UTC 调度分别为前一天 23:35、当天 00:35、01:05、08:10。每日触发后先判断 A 股交易日；GitHub 的免费调度不保证准时，休市与失败都会记录。

每次任务最多 12 分钟。历史数据分批积累，收盘时按带市场时间的报价批量更新已建立的日线，避免每天从头下载。云端保留最近两份不超过 100 MB 的检查点；小型报告按版本保存在私有 `data` 分支，健康附件保留 7 天。

本地同步优先读取 `ASHARE_GITHUB_TOKEN`（细粒度凭据，仅该仓库的 Contents/Actions Read）；没有配置时使用已登录的 `gh` 读取凭据。凭据仅在后端使用，不写入报告或网页。云端使用短期 `GITHUB_TOKEN`，仅任务中允许发布报告和管理自身附件。

首次部署使用本机既有 GitHub 登录。**专用仓库只读凭据尚需账户持有人创建**：在 GitHub Settings → Developer settings → Fine-grained personal access tokens 中，只选择本私有仓库，将 Contents、Actions 设置为 Read-only，然后在本机终端运行 `.venv/bin/python scripts/configure_readonly_token.py`。输入不回显；脚本检查读取权限，凭据文件仅当前用户可读。后台优先使用这份文件，不需要重启。不要把凭据发送到聊天或提交到仓库。

## 数据与判断

- A 股快照、日线、行业和财务：AKShare / 东方财富；报价确认：腾讯财经；海外：Yahoo Finance。
- 每条报价保留来源、行情时间、采集时间。未知延迟不会被标成实时。没有数据时显示缺失，不填充演示行情。
- 交易日历必须明确覆盖当日；不能仅按星期一至星期五推断交易日。
- 原始 OHLC 用于成交，技术指标遇到疑似除权缺口时停止相关筛选。未实施完整历史公司行动数据库。
- 两个实验基线：趋势回踩、放量突破。候选采用可解释规则与相对排序，排序不代表胜率。
- 前 40 个技术候选补充行业趋势、上市日期、财务与公告校验后，最多保留 10 个观察对象。趋势、成交额及波动排序占 90%，行业 20 日趋势占 10%；估值异常、利润大幅下滑、负经营现金流及公告风险触发阻断，权重与阈值尚待样本外验证。
- 本地盘中约每 15 分钟用最新全市场快照和已完成日线重新构建前 40 个技术候选池；每轮监测尝试取得池内报价，以研究排序 90% + 池内当日涨幅排序 10% 重新选择最多 10 只。超出 1 ATR 不追高，跌破 20 日均线、报价过期、公司公告或明确匹配个股的媒体风险报道阻止新增。该盘中排序是 `live-1.0.0` 实验规则，不是经过验证的上涨概率，也未使用全市场逐笔数据。
- 盘中名单与原报告分开保存到 `candidate_versions`；查看原报告时保留当时价格和理由。网页约每 15 秒读取最新数据，个股详情也自动刷新；参考收盘和日线指标仅随已完成日线变化。新闻约每 5 分钟尝试采集，媒体聚合和关键词规则有覆盖限制。上游请求耗时或限流会拉长实际更新间隔；以行情时间和当前状态为准。
- 新闻标题规则标注相关产业与待复核事项；成交前 20 股占比、大幅波动比例、涨跌幅离散度仅作为拥挤代理，不代表真实量化机构仓位。
- 财报必须有可见的披露日期；日期精度不足时保守使用披露日结束时间。新闻保留首次发现时间。
- 当前新闻主要为关键词媒体聚合，未覆盖全部官方政策、公告和行业经营指标；不将未核实消息自动解读为利好或利空。
- 海外日线以交易所当地收盘时间对齐，当前未收盘时只使用已观察到的数据；不把美国当天晚间收盘信息用于 A 股当天早盘。
- 海外与 A 股的相关性不代表因果；目前仅提供统计观察，尚未验证其对策略的增益。
- 主要外围指数最近可见涨跌幅低于 -2% 时，正常环境降为谨慎；这个保守风控阈值尚未完成消融验证。

## 模拟成交与风险

单股上限 20%、行业上限 35%、最多 5 只；正常仓位上限 80%，谨慎 40%，暂停状态不新增。计划单笔风险不超过净值 0.5%；止损不是保证最大损失，跳空、T+1 和封板均可能使实际损失扩大。

本版 `price-plan-2.1.0` 按冻结价格区间触发：首次取得合格当日名单时选择最多 3 只，扣除假设成本后的保守盈亏比至少 1.5。当天不补位、每股只新买一次，名单及原始理由保存在 `daily_plans`。行情、公告及已发现的匹配新闻会继续否决风险条件。

价格到达区间后生成买入意图，只使用后续有效买卖报价成交，滑点后的买入价仍须在区间内。容量上限为信号产生后连续观测到的累计成交量增量的 1%，不足 100 股不成交；不把分钟线缺失补成假 K 线。旧版的完整 5 分钟 K 线确认保留为独立研究对照，本版改变入场规则并另记版本。每笔交易有唯一标识。

离线超过 180 秒会清除未执行订单及成交量基线；不追溯补成交。当天买入不能当天卖出。已观测到的退出意图会跨日保留，恢复后重新等待后续可成交报价。持仓离线期间仍存在，恢复后按当前可见行情估值并重新判断。每日 09:45–14:45 才考虑新增仓位。

手续费是可调整的模拟假设：佣金万三、最低 5 元；卖出印花税万五、过户费十万分之一、单边滑点 10 bp。正式研究应按实际账户和历史适用日期核实。当前历史成本模型不支持 2023-08-28 之前的区间。

## 价格方案与公司情景

每只候选展示建议买入价与允许区间、有效止损和止盈、短线条件目标、净盈亏比、数据日期及逐项理由。趋势回踩参考 MA10 / MA20 和 ATR；突破参考过去 20 日高点，不追随盘中涨价上调已冻结价格。常规止损为建议价 / 实际成交价下方 5%，结合 2 ATR 和趋势位取更紧的保护；常规止盈 8%，与最近技术目标及可得的公司基准情景取较早退出的价格。止损只收紧，利好不取消止损。短线条件目标用于 1–5 个交易日研究，不是收益承诺。

公司价值优先参考至少 2 家机构原研报明确给出的目标价：一家给出区间时取中点，再计算机构中位数及分歧范围。原研报期限不统一，不将该范围冒充 6–12 个月概率区间。机构明确目标价不足时，再采用 6–12 个月条件情景：最近 90 天、同一机构最新一份的下一年度 EPS 预测，乘以同行动态 PE 的四分位 / 中位组合。至少 2 家预测机构及 5 家可比公司；剔除非正和超过 100 倍 PE，同行不含本股与 ST / 退市标记。动态 PE 与远期 PE 口径不同，结果仅是明确假设下的参考，非统计置信区间。金融公司需要另建 PB、资本和资产质量模型，当前不强行给价。来源不够则显示缺口，并保留技术价格。

研报经东方财富公开接口转引，保存机构、标题、预测年份、EPS、原文链接、发布时间及系统首次发现时间；同一报告预测修订后更新首次可见时间。行业研报当前提供匹配分类的研究线索，未逐篇自动核实全文。订单与合同按公告标题区分意向 / 框架、中标与合同阶段；未核实金额、毛利和履约进度，不自动转成利润，也不与研报 EPS 重复计入。搜索未发现不代表没有订单。财报增长、现金流、盈利质量继续参与原有风险过滤。

新增立案、重大违法、债务逾期、业绩预亏、破产、合同终止等明确匹配个股的标题线索，触发保守退出，并保留原始链接；关键词识别可能误判，需结合记录复核。并不宣称能理解所有新闻。T+1 尚不可卖时，退出意图保留到可卖日；涨跌停、缺买盘、陈旧行情和无可用成交量均阻止模拟成交。离线发生而未曾观察到的历史价位不假设已触发交易。

`/api/paper-audit` 导出完整交易、触发信号、冻结名单、入场研究和价格计划、每笔成交报价、容量依据、退出触发时间 / 价格 / 事件及完整净值；后续按策略版本复核，不能直接把短期胜率用于自动调参。规则依据见 [上交所交易规则（2026 年修订）](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)，公开接口说明见 [AKShare 股票数据文档](https://akshare.akfamily.xyz/data/stock/stock.html)。

## 研究与验证

```sh
.venv/bin/python -m pytest -q
.venv/bin/python -m ashare.cli probe
.venv/bin/python -m ashare.cli report --mode local
.venv/bin/python -m ashare.cli backtest 600519 --strategy breakout --cost-multiplier 2
```

`backtest` 是单股日线诊断：收盘后产生信号、下一交易日开盘尝试执行，独立于在线模拟账户。它不是整个历史股票池的无偏回测，也不假装具有分钟入场、历史新闻或退市样本。`research.purged_splits` 提供按时间向前、隔离 5 个交易日的研究切分。

至少观察 20 个交易日运行稳定性；结合 60 个交易日模拟、足够交易样本及独立样本外结果评价策略。当前尚不能宣称策略有超额收益。

模拟盘自动执行符合条件的买卖，无需逐笔人工指定价格。`策略检验` 按策略及版本统计扣费后胜率、平均每笔净收益、平均盈利/平均亏损和已观测最大回撤；一笔买入全部卖完才计一笔完整交易，部分退出的盈亏仍保留在账户中。每笔新成交保存信号时间、原始候选、报告/名单/策略版本、成本设置和当时可见的沪深 300 报价。基准缺失时不补造同期超额收益，基准收益不扣假设交易费用。

`买入到卖出的完整复盘` 展示实际观测成交时间、买卖均价、持有交易日、费用、净收益及退出依据。统计不倒填离线成交、不用事后最优价格评价执行。60 个观察交易日和 30 笔完整交易仅为开始复核的最低提示，不保证显著性；比较新旧策略仍需足够分组样本、按时间隔离的样本外检验及成本敏感性分析。系统持续记录；新增模型必须经过样本外与同风险并行模拟门槛才可接管实验账户的新开仓，不因单日胜负调参。

## 架构与接口

- `backend/ashare`：数据适配、交易日历、策略、报告、同步、模拟账户及 FastAPI。
- `frontend`：React / TypeScript / ECharts 六页工作台。

## 日线覆盖与自动恢复

日线覆盖率 = 当前有成交的沪深主板非 ST 股票中，拥有至少 120 根有效日线且更新到最近完成交易日的数量 / 该股票池数量。它不是胜率，也不是推荐股票比例。历史长度不足仍单列计入分母，不能靠合成数据补成 120 根。数据页面显示应到日期、缺失 / 过期 / 短历史 / 字段异常和补数进度，90% 的新增仓位门槛保持不变。

日线优先使用东方财富，失败后切换新浪原始日线；每批会记住可用来源，限定并发和超时。新浪解码原始成交额及成交量，不用收盘价乘成交量估算成交额，不填充停牌日。价格保持不复权，检查 OHLC 关系、量额单位及除权信息；除权核实失败仍可展示行情，但阻止对应股票自动入场。当日日线在北京时间 16:10 前一律不入库，周末和假日按明确的交易日历定位最近已完成交易日。

全市场快照为东方财富主源单独设置 20 秒上限，超时后用最近有效股票名册分批获取腾讯报价，给备用源留出采集时间；不足 2500 只时不当作完整快照。全轮仍有超时限制，失败时明确显示过期并暂停对应交易信号。

本地登录启动后自动检查历史缺口，在独立后台线程中分批补齐；失败冷却后重试，按上次尝试时间轮换，避免同一批失败股票阻塞其余股票。进度与每股尝试记录落盘，重启接续。补数完成使候选池缓存失效，下轮重新计算市场环境；旧报告的覆盖不足不再永久锁住新的有效评估。原盘前报告保留不改写，实时页面展示最新覆盖及时间。

云端先恢复历史检查点，再同步报告；旧策略报告可校验归档但不能成为当前交易报告。空检查点不会覆盖本地行情，会尝试前一个版本及私有 `data-bootstrap` Release。检查点合并可填补中间缺日，保留本地已有记录，不覆盖模拟账户。只有覆盖至少 90% 的任务才发布新的历史检查点并清理到最近两份；不完整报告仍发布缺口和状态。初始化 Release 是持久备份，不依赖 Actions 缓存。健康收据包含同步结果，不能把任务进程成功当成行情完整。


## 每日选股复盘与模型改进

“模拟盘复盘”提供三个页签：昨日选股、模拟账户、模型改进。复盘保留盘前、盘中及盘后名单的原始时间、价格计划、排名和过滤依据；后续 1/3/5 日结果逐步成熟。研究参考为决策后的第一个完整交易日开盘，持有期以其后交易日计算，缺失/停牌/公司行动未核实单列，不把研究涨幅计入模拟盈亏。盘前名单使用最后一个真正盘前版本，盘中股票使用首次进入重点名单的版本；所有原始版本继续保存。历史没有保存的过滤或执行原因不追溯编造。

新模拟成交记录在线期间实际观测的最高/最低价格，部分卖出合并为一笔完整交易；离线波动不补写。复盘区分“费用抵消价差收益”的可核对证据与“入场时点/止盈规则可优化”的待检验假设，并按模型版本分组；没有记录的旧交易波动保持空值。

原账户 `state.sqlite` 保持旧风险规则；独立实验账户 `state-experiment.sqlite` 从 10 万元开始。实验账户单笔计划风险 0.75%，正常/谨慎/弱市仓位上限 80%/50%/20%，弱市只允许强势行业；市场宽度低于 10% 或关键数据无效停止新增。回撤 8% 后风险和总仓位上限减半，低于 6% 后下一观察交易日恢复；12% 锁定新增且模型更换不解锁。每个持仓保存入场时退出配置。每账户均遵守 T+1、100 股整数手、费用、滑点、实际在线成交量容量及涨跌停规则，不连接实盘。

免费 CPU LightGBM：3 日相对沪深 300 收益回归、20% 下行分位数回归。首版仅使用可重建的量价/市场特征；新闻、公司研报、订单仍为可追溯风险证据，不作为已有历史预测能力。模型估计超额收益不代表绝对收益或上涨概率；下行估计低于 -5% 时单笔预算减半。后续新增数据维度必须变更特征/策略配方版本并重新验证。

固定时间切分为 252 日训练、42 日验证、63 日测试，阶段之间隔离 5 日，成熟标签不足明确阻断；验证只用于早停，测试不选参数。日线研究在收盘决定、下一开盘尝试执行，区间高低不用于推断止损止盈先后；容量使用前日量的 1% 假设。历史行业缺失时两种历史策略总仓位额外限制 35%，弱市不交易，因此这不是分钟执行复现。当前留存股票池仍有幸存者偏差，历史结果不能单独启用模型。

历史通过标准为净收益为正且优于相同规则/风险的对照，最大回撤不超过 12%，成本翻倍仍为正收益且存在完整交易。之后启动独立的同风险规则/模型研究账本（不混入主账户资金）。至少 60 个双方均有充分在线观测的交易日、30 笔完整交易，在线净收益为正并胜过对照后，本地才自动启用模型；单次孤立刷新不计一个有效验证日。固定配方每周可更新权重，特征、风险或入出场规则变化会重新开始验证。启用、回退均记录；已持有仓位保持原计划。

原私有项目既有的云端流程（未迁移到本公开仓库）在 16:10 收盘任务中增加候选复盘，每周六北京时间 08:00 另行训练（Actions 调度可能延迟），每次上限 12 分钟。任务仅上传研究报告和文本模型，SHA-256 校验；不上传本地账户或模型启用控制。免费额度开关沿用现有配置。失败/样本不足保留规则和已有版本。在原私有任务仍启用的情况下，电脑关机时其云端研究继续，本地账户暂停撮合，开机同步后恢复。本公开仓库的代码 CI 不运行这些业务流程。

接口：`GET /api/reviews`、`GET /api/reviews/YYYY-MM-DD`、`GET /api/models`；`GET /api/portfolio` 保留原字段并新增 accounts。切换开关及审计导出支持 `?account=baseline|experiment`。`ashare review` 重算复盘，`ashare train` 手动触发训练；每周已有成功版本时跳过，显式 `--force` 可用于人工研究复核。历史扩展目标为最近约 1100 天，不早于当前费用模型生效日。
